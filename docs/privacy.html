Privacy and data handling

Outlook ICS Normalizer is software installed and controlled by its user. It does not operate an author-hosted calendar service. The author does not receive calendar data through the software.

Data used

The runtime reads the configured ICS feed and copies event titles, descriptions, locations, dates, times and availability into the user's dedicated Google calendar. The configured synchronization window determines which copies are retained. Execution logs can include selected event details.

The deployment client uses basic Google account identity to verify the installation account and Apps Script project access to update its source. Private feed URLs and configuration remain in the user's local files and installed project. Optional GitHub Actions store deployment credentials in encrypted GitHub Secrets and temporarily process project source, including private configuration, on the runner to preserve it during updates.

Control and retention

Users control their configuration, sharing settings and authorized applications. They can stop the timer, remove calendar copies, delete their project or credentials, and revoke access in Google Account settings. Stopping synchronization alone retains existing copies. Google, Microsoft and, when enabled, GitHub process data under their own service policies.

The software does not sell calendar data or use it for advertising. These static documentation pages contain no application analytics or tracking scripts; hosting providers may process ordinary access logs.

For questions, use the project issue tracker. Do not post feed URLs, credentials or private event details.
